# 2026-08-18 问题记录与修复

## 问题描述
修改了应用启动流程相关模块后，在 APK 测试阶段出现启动崩溃。

## 涉及文件
- `log.ts`
- `common.ts`
- `dataInit.ts`

## 根本原因
这三个模块属于启动链路中的脆弱环节：
- `log.ts` 负责外部路径解析与日志初始化
- `dataInit.ts` 负责应用数据目录的初始化流程
- `common.ts` 承载两者之间的共享状态与工具函数

直接重写这些模块的路径逻辑或初始化顺序会破坏启动契约，导致 APK 构建后无法正常启动。

## 修复方案
1. 回退对 `log.ts` 外部路径逻辑的改动，保持原有解析方式不变
2. 恢复 `dataInit.ts` 的初始化流程，不改变模块加载顺序
3. 将功能性调整移到启动链路之外的模块，避免侵入脆弱区域

## 验证结果
- 使用 `.github/workflows/debug-build.yml` 构建 APK debug 包
- 确认主分支构建产物可正常启动
