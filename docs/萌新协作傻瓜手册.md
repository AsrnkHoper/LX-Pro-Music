# 给萌新的 GitHub 协作傻瓜手册

> 写给第一次用 GitHub 的队友。**不用理解原理,按步骤照做就行。**
> 有问题随时问琥珀。

## 先搞懂三个词(就三个)

| 词 | 什么意思 | 打个比方 |
|---|---|---|
| **分支(branch)** | 代码的"副本工作间" | 你在一张草稿纸上改,不影响印好的书 |
| **PR(Pull Request)** | "我改好了,请审核收下"的请求 | 你交作业,老师检查后签名收下 |
| **review** | 别人看你的改动 | 作业有人检查 |

**记住一句话:你永远在"草稿纸"上改,改完交给老师,老师点头才进"正式书"。**

## 场景 1:我只是想放个文档(最简单)

**目的**:把你的文档放到 `docs/你的名字/` 文件夹。

操作(全程网页点点点,不需要命令行):

1. 打开仓库页面 → 点 **docs** 文件夹
2. 点右上角 **Add file** → **Create new file**
3. 路径写 `docs/你的名字/文件名.md`(比如 `docs/小白/我的文档.md`)
4. 下面写内容 → 点 **Commit new file**
   - 此时它直接提交到了 main,没问题(文档自由)
5. ✅ 完成!你的文档在仓库里了

> 💡 想改已有文档:点进那个文件 → 点**铅笔图标(编辑)** → 改完 Commit。

## 场景 2:我要改代码(标准流程)

**目的**:改代码并最终合入。

> ⚠️ 第一次做建议让琥珀或老手在旁边看着,做完一次就熟了。

### 第 1 步:复制仓库到电脑(只做一次)

```bash
git clone git@github.com:AsrnkHoper/lx-lxwalnut-music-mobile.git
cd lx-lxwalnut-music-mobile
```

### 第 2 步:开一个"自己的工作间"(每次开发都做)

```bash
git fetch origin          # 更新信息
git checkout -b feature/我的功能 origin/dev   # 从 dev 开个工作间
```

### 第 3 步:改代码

用编辑器改文件,改完保存。

### 第 4 步:提交(把改动记下来)

```bash
git add 你改的文件        # 选文件(用 git add . 选全部)
git commit -m "feat: 我做了什么"   # 写清楚干了啥
```

### 第 5 步:推到 GitHub

```bash
git push origin feature/我的功能
```

### 第 6 步:在 GitHub 上开 PR

1. 网页会弹"**Compare & pull request**"黄条 → 点它
2. **base: dev**(重要!不是 main)→ compare: 你的分支
3. 标题写清楚 → 点 **Create pull request**

### 第 7 步:等通过

- 会有人 review(检查你的改动)→ 可能留言让你改 → 改完再 push,PR 自动更新
- 绿色 ✅ 都亮了 → 有人点 **Merge pull request**(合并)→ 完成!

## ⚠️ 常见问题(萌新必看)

| 你可能会遇到 | 怎么办 |
|---|---|
| "推不上去,报错" | 先 `git fetch origin` 再 `git pull origin dev` 更新,再 push |
| "PR 显示冲突(conflict)" | 不是你的错,是别人也改了。找琥珀帮忙合并 |
| "要不要直接推 main?" | **不要**!main 有保护,推不上去是正常的 |
| "git clone 要密码?" | 用 SSH 方式(琥珀帮你配一次 SSH key 就行) |
| "我忘了在哪改" | 看 README.md 的项目结构,或问琥珀我该改哪 |

---

## 不需要记住的(放心)

- 哪个分支能推、哪个不能 → 有保护,推错了机器会拦,不会真出事
- 冲突怎么解决 → 遇到再说,琥珀会帮
- main/dev/feature 的关系 → 用多了自然懂,现在照做即可

---

**最后一句:改坏东西不可怕,git 能回滚,大胆试。就怕不敢动。**
