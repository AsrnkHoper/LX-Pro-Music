## 一、卡片套系总览

统一骨架(每张卡都长这样):

```
┌──────────────────────────────────────┐
│  01 · 你的数字              1 / 5     │  ← 顶部:序号标签 + 进度
│                                      │
│           [ 主视觉区 ]                │  ← 大数字 / 图表 / 关键词 / 海报
│                                      │
│      [ AI 一句话 / 数据锚点行 ]       │  ← 简短文案,可有可无
│                                      │
│        ▲ 点按卡面展开这封信           │  ← 交互提示
└──────────────────────────────────────┘
          ● ● ○ ● ●   (底部圆点进度)
```

- **翻卡**:左右横向滑动,一卡一屏(paging)
- **点卡**:点卡面任意处 → 该卡"长文"从底部上滑展开(可滚动),顶部「← 返回卡片」
- **三档卡序**(月/季/年递进,数量 5 / 6 / 8):

| 卡序 | 卡名 | 月度 | 季度 | 年度 | 数据源(schema v2) |
|---|---|---|---|---|---|
| 1 | 封面卡「你的X月」 | ✅ | ✅ | ✅ | `identity.period_name` + `identity.color` + `period` |
| 2 | 大数字卡 | ✅ | ✅ | ✅ | `overview` + `compare`(对比锚点) |
| 3 | 深夜卡「深夜高墙」 | ✅ | ✅ | ✅ | `time`(hourly_heat/late_night_ratio/snooze_guess/session_stats) |
| 4 | 循环之王卡 | ✅ | ✅ | ✅ | `taste.repeat_obsession` + `taste.new_discoveries` |
| 5 | 口味变迁卡 | — | ✅ | ✅ | `taste.genre_shift` + `compare.genre_shift_summary` + `era_taste` |
| 6 | 年度之最卡 | — | — | ✅ | `poster.highlight` + 最活跃一天 + 年度歌手 |
| 7 | 关键词卡 | — | — | ✅ | `identity.persona_tags` + `insights` + `compare.revisit_note` |
| 8 | 海报卡「保存」 | ✅ | ✅ | ✅ | `poster` 全部 + `identity.color` + `overview` |
| 彩蛋 | 情绪卡「安全屋」 | 可选 | 可选 | 可选 | `mood.comfort_songs` + `mood.mood_estimate` |

- **情绪卡是彩蛋卡(2026-08-07 改为本地证据门槛)**:**本地先筛"疑似安全屋"**——跨 ≥2 天重复播放 + 单曲循环次数高(如 ≥5 次/周期,深夜/低落时段占比高加分);筛出 **≥2 首**才触发,AI 再写文案;不足 2 首整卡不出现。判定权在本地事实层,不在 AI 嘴——AI 说了不算,数据说了算。
  - 效果:重度单曲循环党 ~70-80% 出现(对它真的是彩蛋),平均用户 ~40-50%,泛听用户 <20%(不出现反而合理)
  - 实现注:筛歌逻辑本地写死(参考 `taste.repeat_obsession` 的本地计算),AI 只负责给筛出的歌写 note
- **降级原则**:某层数据缺失 → 跳过对应卡;卡数下限 = 封面卡 + 海报卡(2 张),海报卡在 AI 文案缺失时退化为"纯数字海报"(本地拼)。

## 二、逐卡线框图

### 卡 1 · 封面卡「你的X月」

```
┌──────────────────────────────────────┐
│                                      │
│        (整卡底色 = 音乐颜色)           │
│                                      │
│           你的7月:                    │
│         深夜后摇的七月                 │
│                                      │
│   2026.07.01 — 07.31                │

│                                      │

└──────────────────────────────────────┘
```

- **数据源**:`identity.period_name`(周期命名)、`identity.color`(音乐颜色 hex/name)、`period.start/end`
- **示例文案**:
  - 周期名:「你的7月:深夜后摇的七月」
  - 颜色:午夜蓝 `#2E3A5C`(整卡底色,白字)
- **长文(信的开头)**:「嗨,是我。7 月你听了 428 次,累计 52 小时。这不是一份报告,是我想跟你聊聊:这一个月,你都在听什么、为什么在听。慢慢看。」
- **降级**:
  - 无 `period_name` → 标题用「我的7月听歌报告」(兜底,不空着)
  - 无 `color` → 用品牌主色(策划 5.2 已定:封面主色 → 流派/调性映射 → 品牌色)

### 卡 2 · 大数字卡「这个月,你听了」

```
┌──────────────────────────────────────┐
│  02 · 你的数字              2 / 5     │
│                                      │
│      428     52小时     21天          │
│      次播放   累计      活跃          │
│                                      │
│  次数比6月多43%,但总时长少了12%      │  ← 对比锚点行(compare)
│  你更频繁地开始,更快地切掉            │  ← AI 一句话
│                                      │
│        ▲ 点按展开这封信               │
└──────────────────────────────────────┘
```

- **数据源**:`overview.total_plays` / `total_duration_min` / `active_days` + `compare.plays_delta_pct` / `duration_delta_pct`
- **示例文案**(注意:`total_plays` 是次数不是首数,口径准确)
  - 大数字:428 次播放 · 52 小时(3120 分)· 21 天
  - 对比锚点:「次数比 6 月多 43%,但总时长少了 12%」→ AI 解读「你更频繁地开始,更快地切掉」
- **长文**:「428 次,52 小时,21 天。次数比 6 月多了 43%,总时长反而少了 12%——你在更快地切歌。最沉的一天是 7 月 12 日,单日 3 小时 11 分;最空的一天是 7 月 21 日,只完整听完 2 首。那个 12 日,你大概很需要音乐。」
- **降级**:`compare` 缺失 → 只显示三列大数字,不显示对比行

- **数据源**:`time.hourly_heat`(24 格)、`late_night_ratio`、`snooze_guess`、`session_stats`

- **降级**:`snooze_guess` 缺失 → 只显示数据与可视化,不显示推断(诚实降级)

## 三、交互规格

| 交互 | 规格 |
|---|---|
| 翻卡 | 横向滑动,pagingEnabled,一卡一屏;底部圆点进度(第几张/共几张) |
| 点卡 | 卡面点按 → 长文从底部上滑展开(覆盖层,可滚动),顶部「← 返回卡片」;长文末尾「回到卡片」 |
| 长文定位 | 每张卡长文 = 该维度的信件正文(不是整封信一次吐完),与卡一一对应 |
| 生成中 | 三态等待:「正在读你的数据…」→「正在写你的一月…」→「正在装信…」,完成后自动落在封面卡 |
| 历史报告 | 统计页顶部「历史报告」入口:按 月/季/年 分组的横向小封面列表,点进重看完整故事流(缓存离线可看) |
| 用户改文案 | 长文与海报 headline 可编辑,存本地,标注「已编辑」;不重烧 token |
| 重新生成文案 | 海报卡按钮 → 确认弹窗 → 烧一次 token;频控:同一周期最多 3 次/天;若已手动编辑过,先提示将覆盖修改 |
| 保存 | 海报卡「保存到相册」→ toast 确认;不做分享链路(维持克制,用户自己拿去发) |
| 离线 | 报告缓存(`@stats_report` + 数据指纹)后,离线完整可看 |

## 四、降级矩阵

| 情况 | 行为 |
|---|---|
| 某层数据/AI 字段缺失 | 跳过对应卡(封面卡 + 海报卡永在) |
| 卡数下限 | 至少 2 张(封面 + 海报),海报退化为纯数字版 |
| AI 原创字段缺失 | 卡显示数据但无解读文案(诚实降级,不硬编) |
| 情绪卡条件不满足 | 不出现(本地证据门槛:疑似安全屋 <2 首;彩蛋逻辑,不是报错) |
| 年度首周期 / 季度首周期 | 无对比数据 → 口味变迁卡跳过,其余照常 |

## 六、报告卡片 v2 设计(2026-08-14 琥珀拍板,开发中)

> 背景:琥珀反馈"每次同样卡片、没人情味、随机性低"。调查发现根因:① App 链路把 AI 返回的文案丢了(只剩本地数据,从没见过 AI 的话) ② 卡片数字混口径(top_song 198次是全年累计,total_plays 71次是本周) ③ 缓存指纹未变返回同一份。

### P0 必修
1. **AI 文案不丢**:本机实测 mimo-v2.5 用相同 prompt 完整返回 identity/stories/poster/insights,App 里却只剩本地数据 —— 修 App 解析/请求链路,确保 AI 原创字段进报告。修好琥珀才能看到 AI 的话。
2. **数据口径统一**:top_song/top_artist/循环之王/新发现 全部按**本周期内**过滤重算(不能混全年累计)。total_plays 与 top_song.plays 必须同口径。

### P1 体验
3. **缓存策略**:缓存的是完整 AI 报告;若生成走了兜底(仅本地数据),不入缓存/档案馆,下次仍真请求。
4. **语气更自由**:temperature 0.8 → 1.0。
5. **每次生成换角度**(随机角度提示词,如"这次从深夜维度切入/从循环之王切入"),事实不变、角度可换,解决"随机性低"。

### 卡片风格(琥珀选"都要")
- **封面卡**:AI 命名大字(period_name,Spotify 风)+ 音乐颜色底色
- **中间卡**:每卡一句 AI 真心话(像懂你的朋友说的)+ 数字/可视化并存

> 背景:琥珀反馈"卡片无聊、没惊喜感,生成来生成去就那几种"。根因:卡型写死 + AI 被 schema 锁死,只会念数据。

### 结构(固定 + 动态)
```
封面卡(固定) → [AI 从菜单挑 3-6 张] → [surprise 惊喜卡 0-1 张] → 海报卡(固定)
```

"cards": [
