# 01 · 调查成果

> 本文档汇总对 `lx-lxwalnut-music-mobile` 项目"听歌统计"页面相关代码库的完整调查结果。所有结论均来自实际文件读取，标注了 `文件路径:行号`。

## 一、存储架构总览

### 1.1 不使用 Redux / MMKV / SQLite / Realm

项目仅有一层 **AsyncStorage 键值存储**（`@react-native-async-storage/async-storage`），由 `src/plugins/storage.ts` 封装。

- 每个键存为单个 JSON 字符串 blob（整个数组序列化）
- `storage.ts:9` 的 `limit = 500000`（500KB）是分片阈值——超过则拆分为多个 `@___PART_A___` 子键存储，读取时自动重组为完整对象
- **没有索引、没有分页、没有按字段查询**，所有"查询"都是内存数组 `filter`/`sort`

### 1.2 所有 AsyncStorage 键注册表

定义在 `src/config/constant.ts` 的 `storageDataPrefix`。与统计直接相关的键：

| 键 | 内容 | 保留期 | 类型定义文件 |
|---|---|---|---|
| `@stats_daily` | 每日聚合（plays/duration/active） | **永久** | `src/types/stats.d.ts` → `LX.Stats.DailyItem` |
| `@stats_song` | 歌曲维度聚合（累计次数/首末播放时间） | **永久** | `LX.Stats.SongItem` |
| `@stats_events` | 原始播放事件（含完整 musicInfo 摘要） | **90 天** | `LX.Stats.EventItem` |
| `@play_history` | 播放历史（带 listId/source） | 31 天 / 上限 5000 | `src/types/player.d.ts` → `LX.Player.PlayHistoryItem` |
| `@stats_report` | AI 周报缓存（带 fingerprint） | — | `AiReportV2` + fingerprint |
| `@stats_report_archive` | AI 报告档案（上限 30 份） | — | `ArchiveItem[]` |
| `@setting_v1` | 全部用户偏好（含 AI 配置/主题/导航顺序） | 永久 | `src/types/app_setting.d.ts` → `LX.AppSetting` |
| `@dislike_list` | 不喜欢的歌/歌手规则 | 永久 | `LX.Dislike.DislikeInfo` |

### 1.3 三张统计表的 Schema（`src/types/stats.d.ts`）

```typescript
interface DailyItem {       // @stats_daily — 永久，按天一条
  date: string             // YYYY-MM-DD
  plays: number            // 有效收听次数（累计 ≥120s 或 ≥50% 算一次）
  duration: number         // 实际播放秒数（不受阈值限制）
  active: boolean          // 当天是否有 ≥1 次有效收听
}

interface SongItem {        // @stats_song — 永久，每首歌一条
  id: string               // musicInfo.id
  name: string
  singer: string
  album: string
  plays: number            // 有效收听次数
  duration: number         // 实际播放秒数
  firstPlayedAt: number    // 首次播放时间戳
  lastPlayedAt: number     // 最近播放时间戳
}

interface EventItem {       // @stats_events — 只留 90 天，每次结算一条
  id: string               // `${songId}_${playedAt}`
  musicInfo: LX.Music.MusicInfo  // 完整歌曲摘要
  playedAt: number         // 播放开始时间戳
  playTime: number         // 实际播放秒数
  maxTime: number          // 歌曲总时长秒数
  isEffective: boolean    // 是否有效收听
}

interface Overview {
  totalPlays: number
  totalDuration: number    // 秒
  activeDays: number
}
```

### 1.4 统计口径（`src/core/player/stats.ts:13-16`）

- **有效收听** = 累计 ≥120s **或** ≥50% 歌曲时长 → 只影响"次数/排行/活跃天数"
- **时长统计** = 实际播放秒数累加，不受阈值限制 → 影响总时长/热力图深浅
- **入账门槛**（`stats.ts:69-79`）：正常歌 ≥30s 且 ≥50%；短歌（<30s）需听完 100%

## 二、数据写入流程

### 2.1 触发层（`src/core/init/player/stats.ts`）

- 订阅 `global.app_event` 的 `musicToggled`/`pause`/`playerEnded`/`play`
- 用独立的 `BackgroundTimer.setInterval`（**2 秒轮询** `getPosition()`）
- **不依赖 `playProgressChanged`**——因为该事件在锁屏时停止，会丢失锁屏听歌时长
- `AppState` 'active' 转换时立即补一次轮询，捕获锁屏期间播放
- 首次启动若三表为空，调 `backfillStatsFromHistory()` 从 `@play_history` 回填

### 2.2 结算写入（`src/core/player/stats.ts:60-141`）

`addStatsRecord(params)` 流程：
1. 入账门槛检查（短歌/正常歌分别处理）
2. `getDataMultiple` 一次性读三张表
3. 更新 `DailyItem`（找到当天或新建，`plays++`、`duration += playTime`）
4. 更新 `SongItem`（找到该歌或新建，`plays++`、`duration += playTime`、更新 `lastPlayedAt`）
5. 追加 `EventItem`，清理 90 天外过期事件
6. `saveDataMultiple` 一次性写三张表
7. `emit global.app_event.statsUpdated()`

写入由 `addStatsRecordQueued`（`stats.ts:145-149`）串行化，避免并发覆盖。

### 2.3 播放历史写入（`src/core/init/player/playHistory.ts` + `src/core/player/playHistory.ts`）

- 触发：`musicToggled` + `playProgressChanged`，当 `nowPlayTime >= 120s` 或 `>= 50%` 时
- `addPlayHistory` 串行化写入，同歌同天去重（替换当天旧记录）
- 保留 31 天 / 上限 5000 条
- `source` 字段从 `listId` 推导：`search` → 'Search'；`dailyrec_*`/`heartbeat`/`similar_songs_list` → 'Rec'；`artist_detail_*`/`album_*` → 'Detail'；其余 → 'List'

## 三、查询 API（`src/core/player/stats.ts`）

全部 async，每次调用全表加载后内存 filter：

| 函数 | 返回 | 使用场景 |
|---|---|---|
| `getStatsDaily()` | `DailyItem[]` 全量 | 内部 |
| `getStatsSong()` | `SongItem[]` 全量 | 内部 |
| `getStatsEvents()` | `EventItem[]` 全量（90天） | 内部 |
| `getStatsDailyByRange(start, end)` | `DailyItem[]` 范围过滤 | 热力图/年度/趋势 |
| `getStatsDailyByDay(date)` | `DailyItem \| null` | 选中当天时长 |
| `getStatsEventsByDay(date)` | `EventItem[]` 当天 | 当天账本明细 |
| `getStatsOverview(start?, end?)` | `Overview` | 概览三数字 |
| `getStatsTopSongs(limit=50)` | `SongItem[]` 按次数降序 | 歌曲排行 |
| `getStatsTopArtists(limit=50)` | 按 singer 聚合后降序 | 歌手排行 |
| `exportStatsData()` | `{type,version,daily,song,events}` | 备份导出 |
| `importStatsData(data)` | 覆盖三张表 | 备份导入 |
| `deleteStatsDay(date)` | 删除当天数据 | 长按热力图格 |
| `clearStats()` | 清空三表 | 设置页 |
| `backfillStatsFromHistory()` | 从 play_history 回填 | 首次迁移 |

### 已知问题

1. **重复全表加载**：Stats 页一次刷新并发调 `getStatsOverview + getStatsTopSongs(10) + getStatsTopArtists(10)`，其中 `getStatsSong()` 被调两次（TopSongs 和 TopArtists 各一次）
2. **歌手排行仅按 `singer` 字符串聚合**（`stats.ts:308`），未用 `artists[]` 结构，多歌手/合作曲目会失真
3. **排行播放 bug**（`index.tsx:90`）：硬编码 `source:'kw'`，stats 存的是摘要 musicInfo，实际可能无法播放

### 4.3 报告生成流程（`src/core/stats/report.ts`）

```
generateWeeklyReport(force)
  ├─ getAiConfig()                        // 从设置读 endpoint/key/nickname/tone/model
  ├─ getCurrentWeekRange()                 // 周一 00:00 ~ 周日 23:59
  ├─ buildPeriodFacts(start, end)          // 本地算 overview/time/taste（<2KB 请求体）
  │    ├─ getStatsDailyByRange(start, end)
  │    ├─ getStatsEvents() → 过滤 inRangeEvents
  │    ├─ 聚合 topSongs / topArtists（周期内）
  │    ├─ 算 late_night_ratio（23:00-05:00 播放时长占比）
  │    ├─ 算 session_stats（次数/均长/最长）
  │    └─ taste.repeat_obsession / new_discoveries
  ├─ 缓存检查（fingerprint = start-end|total_plays|total_duration_min|active_days）
  ├─ buildAiSystemForReport()              // 系统提示（18 卡型菜单 + schema 要求）
  ├─ chatCompletion({capability 三层降级})  // json_schema > json_object > none
  ├─ parseReportV2(raw)                   // 容错：去 ```json 包裹 / 字符串再解析
  ├─ validateReportV2(parsed)             // 校验 identity/cards/poster 必填
  ├─ 失败重试一次（告诉 AI 缺了什么字段）
  ├─ finalizeReport(raw, facts, period)   // 本地事实层覆盖 AI 漏的/错的字段
  ├─ saveReportCache(period, facts, report)
  └─ addReportToArchive(report)           // 追加档案，最多 30 份
```
