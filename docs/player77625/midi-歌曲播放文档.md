## 一、一句话介绍

> **把任何 `.mid` / `.midi` / `.kar` 乐谱文件当作一首歌来播放** —— 解析 MIDI 事件流,内置软件合成器实时"演奏"出 PCM 音频,编码为通用 MP3 音频,然后**原封不动地复用整个音乐播放器链路**(进度 / 切歌 / 通知栏 / 歌词 / 历史记录)完成播放。

MIDI 本身不携带任何声音,它只是"乐谱"。本引擎就是在手机里养了一个**虚拟乐手剧组**:有人读谱、有人演奏、有人录音、有人分发。

## 二、为什么需要它

| 层面 | 根因 |
|---|---|
| **播放引擎** | `react-native-track-player`(Android 走 ExoPlayer / iOS 走 AVPlayer)只播放**已渲染的音频文件**。MIDI = 事件序列,不是波形,必须经合成器渲染才有声音 |
| **运行时限制** | Hermes 引擎无 WebAssembly、无 Web Audio API,浏览器方向的合成方案(Tone.js、FluidSynth-WASM、WebAudio)全部不可用 |
| **产品空白** | 用户常收到同学/老师/MIDI 教学曲,或网上下载的钢琴谱;本站没有能力打开,只能灰掉 |
| **成本诉求** | 不做原生模块(零 native 编译负担),不引入云端渲染(歌曲是本地文件,不该出网) |

## 五、核心流水线

一次播放,引擎内发生的故事:

```
  ① 解析        MIDI 二进制 → SMF 事件流 → 规整音符表
  ② 编排        MusicInfo 落地(时长 / 名称 / 来源 local)
  ③ 命中缓存?   ── 是 ──► 直接返回 file:// 旧音频(秒开)
             └─ 否
  ④ 合成        逐音符渲染 PCM(44.1kHz 立体声 Float32Array)
  ⑤ 编码        PCM → MP3(128kbps)[失败 → WAV]
  ⑥ 落盘        写入私有目录 midi/<hash>.mp3
  ⑦ 投递        file:// 交给 TrackPlayer,与普通歌曲无异
```

### ① 解析(`parse.ts`)

- `@tonejs/midi`(纯 JS,零依赖)读取 SMF 文件 → 得到**结构化乐谱**
- 推导产物:`ParsedMidi { duration, bpm, notes[], programs{}, hasDrums }`
  - `notes[]`:每个音符的 { 音高(0-127)、时分、起始、速度、通道、音色程序号 }
  - `hasDrums`:是否含通道 9(打击乐)标记,决定合成时是否启用鼓组渲染
- 读文件走 `readFile(path, 'base64') + Buffer` 二进制无损通道;毫秒级完成

### ② 编排(`index.ts` → `buildMidiMusicInfo`)

- 产出标准 `LX.Music.MusicInfoLocal`:`source: 'local'`、`meta.ext: 'mid'`
- `interval` = `formatPlayTime2(duration)` → 列表页展示时长,播放器进度轨自动生效
- **不新增源类型** —— 列表、队列、历史、推荐去重全部沿用现有逻辑

### ⑦ 投递

- 返回 `file://` 绝对路径 → `getMusicUrl` 原有返回通路 → 播放器原生解码
- MP3 为通用格式,ExoPlayer / AVPlayer 原生支持,播放性能与普通歌曲一致

## 六、合成引擎详解

### 6.1 参数基线

| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 44 100 Hz | CD 标准 |
| 波表长度 | 4 096 | 单周期采样表,相位累加无毛刺 |
| 立体声 | 2 ch | Float32 交织渲染,分左右缓冲 |
| MP3 码率 | 128 kbps | 体积 / 音质平衡 |
| 编码帧块 | 1 152 samples | LAME 标准帧 |

### 6.2 发声模型(ADSR 简化包络)

- **起音(Attack)**:线性爬升(短促,避免爆音)
- **衰减(Decay)**:指数衰减,时间常数由音色族决定
- **释放(Release)**:音符结束后 100ms 平滑淡出,防咔嗒声
- 力度映射:`增益 = 音色增益 × max(0.05, velocity)` —— 轻触弱奏、重击强奏,还原乐谱表情

### 6.3 音色族与 GM 映射

GM 程序号(0-127)→ 按族归类,一琴多用:

| 音色族 | 覆盖典型 GM 区间 | 性格 |
|---|---|---|
| `piano` | Acoustic/Electric Piano、Harpsichord… | 主打,清脆颗粒 |
| `organ` | Church/Reed/Accordion… | 管风琴,持续音色 |
| `bass` | 各类贝斯 | 低频铺底 |
| `strings` | String Ensembles、Choir… | 丰厚群感 |
| `guitar` | Acoustic/Electric Guitar… | 拨弦质感 |
| `brass` | Trumpet/Trombone/Sax… | 明亮铜管 |
| `default` | 其余一切 | 通用兜底 |

### 6.4 鼓组(通道 9 / 10 GM 打击乐)

```text
35/36  底鼓   —— 强拍地板
37/38/40 军鼓  —— 节奏骨架
42/44/46/54 踩镲/开镲/吊镲 —— 律动明暗
39/41/43/45/47/48/50 通鼓  —— 加花
```

一律按**非音调打击乐**渲染(短衰减噪声混合/定音),不参与音高映射。

### 6.5 立体声与限幅

- **声道偏置**:`通道 % 2` 决定单音符左右增益(1.0 / 0.86),同轨既有空间又不过度
- **归一化 + tanh 软限幅**:峰值贴到 0 dB 前,过冲被软剪,听感不破、功放不裂
- 输出峰值实测 ≤ 0.764(多轨 12 事件样本),无削波

## 七、缓存与性能

| 项目 | 策略 |
|---|---|
| 目录 | 应用私有目录 `…/midi`(不占用户可见空间、随应用清除) |
| 键 | `md5(文件路径_修改时间_目录)` —— 内容变更即新键,自动重合成 |
| 格式 | **MP3 优先**;合成时若 MP3 编码失败,落 WAV 兜底,下次命中 WAV |
| 上限 | 30 个文件,超出自动清理最旧 |
| 预热 | `prewarmMidiCache()` 支持列表页静默预合成,点开即播 |
| 预估耗时 | 典型 3 分钟曲目:合成+编码 5–20 s(视设备算力);缓存后 <1 s |

> 内存峰值 ≈ 3 分钟 × 2ch × 44.1k × 4B ≈ 63 MB 缓冲区(分块处理,实际常驻更低),对现代机型友好。

## 九、设计决策录

| 决策 | 选项 | 胜出 | 理由 |
|---|---|---|---|
| 渲染路线 | A 纯 JS 合成 / B WebView+FluidSynth / C 原生模块 | **A** | 零原生、零网络、Hermes 兼容;B/C 音质和能力更好但违背「不伸手」约束;C 双端维护成本 |
| 交付格式 | WAV / MP3 / OGG | **MP3 优先, WAV 兜底** | MP3 体积小 10 倍 + 双端原生解码;WAV 是零依赖保险丝 |
| 音色方案 | Sampled / 波表 / FM | **波表** | 免第三方音源资产(几十 MB),音色可接受 |
| MIDI 范围 | 仅 .mid / 含 .kar | **均可** | .kar 是 Karaoke 变体,同一解析链 |

## 十二、兜底与降级

```
正常     file:// <cache>/<hash>.mp3    → 直播
  │
  ├─ MP3 编码异常 ────────────► file:// <cache>/<hash>.wav(原生直接播)
  │
  ├─ 解析失败(损坏/格式怪) ──► 确认弹窗即终止,不进播放队列
  │
  └─ 磁盘写入失败 ────────────► 报错文案,不崩溃、不残留半成品
```

- 播放器侧:URL 无效即原有错误流,不特殊处理
- 状态提示:合成全程 `setStatusText('正在合成 MIDI 音频… xx%')`,完成由播放进程接管,体验无跳变

## 十四、风险透视

| 风险 | 等级 | 缓解 |
|---|---|---|
| 长曲(>5 min)合成耗时 | 中 | 进度文案 + 缓存兜底;预热 API 支持列表静默合成 |
| lamejs 设备端行为与 Node 差异 | 低 | 已走 exports ESM 具名导入;降级到 WAV 兜底 |

| 与存量 245 个 tsc 债务交叉 | 低 | 实验证明非本功能引入 |
