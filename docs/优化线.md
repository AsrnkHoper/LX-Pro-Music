# LX Music Pro — 优化线(性能/流畅度方向)

> 建立:2026-08-18 · 琥珀提出"很多地方不够丝滑不够流畅"(启动/设置/年度热力图等)
> 定位:给开发者的**性能优化方向清单**。方向性 + 可量化目标——每个优化项要能"测得出变好了"

## 〇、一句话

**快不是"不卡",是"感觉不到在等"。** 优化追求:启动秒开、切换零等待、滚动 60fps、内存平稳。

## 一、已知问题点(琥珀已观察到 + 历史已知)

| 痛点 | 现状 | 方向 |
|---|---|---|
| **App 启动加载久** | 启动慢 | 启动链路优化:懒加载/预加载/启动页过渡 |
| **打开设置页加载久** | 设置页慢 | 设置项懒渲染/缓存 |
| **年度热力图加载久** | 一年 365 天渲染慢 | 已做分批渲染(5c538e8)但仍不够:进一步虚拟化/简化重排 |
| **列表滚动卡顿** | (歌曲/排行大列表) | FlatList 虚拟化/行组件 memo |
| **图片加载慢** | 封面/专辑图 | 图片缓存/占位/渐进加载 |
| **统计计算慢** | 大量事件聚合 | 数据库索引/聚合缓存 |

## 二、优化方法论(给开发者的三条)

1. **先测后改**:优化前先量化(加载耗时/帧率/内存),改完再测对比——"感觉快了"不算,要有数字
   - 工具:React Native DevTools Performance、`adb shell dumpsys`、启动耗时埋点
2. **抓大头**:80% 的卡顿来自 20% 的热点(最常见的:不必要的重渲染、大列表全量渲染、图片无缓存)。先定位再改,别盲优化
3. **可回退**:每次优化是独立 commit + 标注"优化前 Xms → 优化后 Yms",方便追溯和回退

## 三、候选优化项(方向性)

### 启动/框架层
- **启动加速**:分析启动链路,懒加载非首屏模块,缩短冷启动
- **JS bundle**:拆包/按需加载(减少首屏下载和执行)
- **运行时内存**:降低基线内存,防 OOM

### 页面/渲染层
- **设置页**:懒渲染 + 缓存,打开不卡
- **统计页**:年度/月度热力图渲染优化(虚拟化/Canvas)
- **列表**:FlatList 参数调优(initialNumToRender/windowSize)、行 memo、去除不必要的 setState

### 数据层
- **统计查询**:`@stats_daily/@stats_song/@stats_events` 的读写优化(索引/聚合缓存)
- **AsyncStorage**:大 key 读写优化/精简
- **图片**:封面缓存策略 + 渐进加载

### 动效层
- 动画 useNativeDriver 化
- 避免布局抖动(尺寸突变→占位)

## 四、已有优化(别重复做)

- ✅ 年度热力图分批渲染(5c538e8)——但需进一步优化
- ✅ CI 构建缓存加速(cc79d25)
- ✅ 依历史踩坑:动效时长 200-400ms,不生硬跳变
